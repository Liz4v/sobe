# Spec: sobe 1.0.0 release readiness

**Status:** Draft
**Created:** 2026-07-11
**Scope:** Everything required before tagging `1.0.0`. List filtering for `--list`
is explicitly **out of scope** — it will be specced separately and must land as an
additive (non-breaking) change after 1.0.

## Background

sobe is at 0.4.1.1 with 56 tests at 100% coverage, Sphinx docs on Read the Docs,
and PyPI trusted publishing gated by tag/version validation. Going 1.0 turns the
CLI surface into a compatibility contract. Four work items close the remaining
gaps.

---

## 1. CI workflow for tests and lint

**Problem:** The only workflow ([.github/workflows/pypi.yaml](../.github/workflows/pypi.yaml))
builds and publishes. Nothing runs pytest or ruff on push/PR, and the claimed
Python 3.11–3.14 support (pyproject classifiers) is never exercised.

**Implemented (2026-07-17):** `.github/workflows/test.yaml` added as specced;
lint job also runs `uv run ty check` (item 4). All four Python versions
verified passing locally via `uv run --python <ver> pytest`.

**Requirements:**
- New workflow `.github/workflows/test.yaml` triggered on `push` to `main`,
  `pull_request`, and `workflow_dispatch`.
- Test job matrix over Python 3.11, 3.12, 3.13, 3.14, using uv
  (`uv run --python <ver> pytest`); the existing coverage gate
  (`--cov-fail-under=95` from pyproject) applies as-is.
- Lint job (single Python version): `uv run ruff check` and
  `uv run ruff format --check`.
- Workflow uses the same uv install pattern as pypi.yaml for consistency.

**Acceptance criteria:**
- A PR that breaks a test, drops coverage below 95%, or fails ruff shows a red check.
- All four Python versions pass on current `main`.

## 2. First-run experience: interactive setup wizard

**Problem:** Today, first run writes a template config and exits 1 telling the
user to go edit it — an uncommon and unfriendly pattern that drops the user at
the moment they know least about the tool. Worse, [main.py:20-28](../src/sobe/main.py#L20-L28)
calls `load_config()` before `parse_args()`, so `sobe --help` and
`sobe --version` on a fresh machine create a config file as a side effect and
exit 1 instead of answering.

**Decision (resolved 2026-07-11):** replace write-and-exit with an interactive
first-run wizard.

**Superseded and implemented (2026-07-15) via `specs/first-run-onboarding/`:**
the wizard was deliberately dropped — the gap between "has an AWS account" and a
working bucket + CloudFront distribution + ACM certificate + DNS CNAME is real
infrastructure work that a handful of CLI prompts cannot close or verify.
Shipped instead: argument parsing now runs before any config access
(`--help`/`--version` answer and exit 0 on a fresh machine without touching the
filesystem, fixing the bug described above), the write-template-and-exit-1
first-run behavior is **retained** (including for bare `sobe`), and both
first-run messages now point to the new onboarding tutorial page
(`docs/tutorial.md`, printed as its Read the Docs URL). The wizard-specific
requirements and acceptance criteria below (TTY prompts, wizard validation and
abort handling, the non-TTY "no file is created" rule) no longer apply — the
template is still written whenever a config-needing command runs with no config
present.

**Requirements:**
- Argument parsing happens before any config access, so `--help`/`--version`
  work (and exit 0) with no config present and never touch the filesystem.
  Bare `sobe` still prints help and exits 0 without touching config.
- When a command needs config and none exists (or it is unconfigured per the
  multi-target schema's test: zero targets, or every target's bucket still the
  `example-bucket` placeholder) **and stdin is a TTY**: run an inline wizard
  that sets up a single default target named `main`, prompting for —
  1. S3 bucket name (required),
  2. public base URL (optional; normalize: ensure trailing `/`; skipping
     omits the `url` key),
  3. CloudFront distribution ID (optional; skipping omits the whole
     `[target.main.cache]` table) —
  then writes the config in the multi-target schema (preserving the commented
  `[target.main.aws_session]` / `[target.main.aws_service]` sections from the
  current template as advanced options), confirms the saved path, and
  **continues executing the command the user originally typed**.
- Each prompt validates minimally (bucket non-empty; URL, if given, must
  parse as http/https). Ctrl-C / EOF during the wizard aborts cleanly without
  writing a partial file. The wizard must never overwrite an existing
  configured file, and per the multi-target spec an existing-but-unconfigured
  file is the user's to edit — the wizard may rewrite it only after
  confirming with the user.
- **Non-TTY** (pipes, CI): no wizard, no file written. Print a one-line error
  naming the expected config path and the docs URL, exit 1. This replaces the
  current template-write side effect in non-interactive contexts too.
- Editing the config file directly remains the documented advanced path;
  the multi-target schema's unconfigured test (`Config.is_unconfigured()`:
  zero targets, or every bucket still the placeholder) is retained as the
  wizard trigger.
- README and Sphinx configuration docs updated to describe the wizard as the
  primary onboarding path.
- `MustEditConfig` exception is repurposed or removed as fits the new flow.

**Acceptance criteria:**
- With no config file present: `sobe --help` and `sobe --version` exit 0 and
  create nothing.
- With no config and a TTY: `sobe photo.jpg` runs the wizard, writes a valid
  config, and proceeds to upload in the same invocation.
- With no config and stdin not a TTY: exits 1 with the pointer message and no
  file is created.
- Wizard-written config round-trips through `load_config()` identically to a
  hand-edited one.
- New tests cover: wizard happy path (prompts monkeypatched), each validation
  rejection, abort mid-wizard, and the non-TTY path.

## 3. CLI freeze audit

**Problem:** After 1.0, renaming a flag or changing its semantics is a breaking
change. Ambiguities must be resolved now.

**Requirements:**
- `-y/--year` actually means "remote directory" (arbitrary values are accepted).
  **Decision (resolved 2026-07-11, flag spelling revised to `--prefix`
  2026-07-13):** promote `-p/--prefix` as the documented
  name; keep `-y`/`--year` as working aliases; `--policy` becomes long-only,
  donating `-p`. (`--dir` was rejected: `-d` belongs to `--delete`, which is
  frequent and destructive — the wrong flag to destabilize.) Companion
  decision in `specs/multi-target/Architect.md`: `-t` is reassigned from
  `--content-type` (which also becomes long-only) to the new `--target`
  selector. Rationale for both: the two rarest flags donate their
  letters to the two everyday selectors, and both breaks ship inside the same
  major bump as the config-schema change.
  **Implemented** via `specs/prefix-flag-rename/` (2026-07-13): `-y`/`--year`
  remain functional aliases through 1.x, emit a one-line stderr deprecation
  warning, and are removed in 2.0; leading slashes in the prefix value are
  now stripped (`--prefix /` and `--prefix //` mean the bucket root,
  `--prefix /2024` means `2024/`), closing the 0.x footgun where a leading
  slash produced a literal `/`-prefixed S3 key.
- `--list` help text says filtering is not supported "yet" — confirmed: the
  future filtering feature must be additive (positional args currently rejected
  with `--list` become filters). No change needed now beyond confirming the
  error message doesn't preclude that.
- One pass over all flag combinations in `parse_args()`
  ([main.py:59-113](../src/sobe/main.py#L59-L113)) to confirm each error/success
  path is intended, since each becomes a contract.
  **Done (2026-07-17).** All paths confirmed intended, with one fix and two
  accepted behaviors:
  - Fixed: `--list --invalidate` was accepted but the invalidation was
    silently skipped (`main()` returns from the list branch before the
    invalidation block). Decision: reject the combination, matching
    `--list --delete`; could be relaxed additively later.
  - Accepted as policy: an empty-string option value is equivalent to the
    flag being absent (`-t ""` was already tested as intended; `--prefix ""`
    alone therefore shows help and exits 0 rather than erroring).
  - Accepted (cosmetic): `--policy --year X` prints the `--year` deprecation
    warning before erroring on the combination.
  - Exit-code contract for the release notes: 0 success/help, 1 config
    problems and missing local files, 2 usage errors.

**Acceptance criteria:**
- Open questions below are resolved and reflected in code/docs.
- README and Sphinx usage docs match the final flag set.

## 4. Static type checking

**Problem:** The code is fully annotated but nothing enforces it.

**Requirements:**
- Add a type checker to the `dev` dependency group.
  **Decision (resolved 2026-07-17):** ty (astral.sh). **Implemented** same day:
  `ty` added to the dev group; findings fixed (assert-narrowing in
  `AWS.invalidate_cache`, removed a stale `# type: ignore` in main.py, one
  intentional-bad-type test suppressed). `uv run ty check` passes clean.
- Add its invocation (`uv run ty check`) to the lint job in the new CI
  workflow (item 1) — done 2026-07-17 with item 1.

**Acceptance criteria:**
- Type check passes clean in CI on all of `src/`.
